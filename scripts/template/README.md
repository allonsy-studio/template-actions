### Architecture

```text
src/
  index.js       # entry shell: reads the `token` input, builds the octokit
                  # client, calls main(), and maps a thrown error to
                  # core.setFailed()
  main.js         # the action's actual logic — edit this
  main.test.js    # jest coverage for main.js
dist/
  index.mjs       # generated by @vercel/ncc — the dependency-free bundle
                   # action.yml actually runs. Gitignored: not committed to
                   # main, only built (and committed) at release time.
```

GitHub runs `uses: {{ OWNER }}/{{ ACTION_NAME }}@vX` by executing
`dist/index.mjs` directly from that ref — no install step. Rather than
committing `dist/` to `main` (generated code in every PR diff and dependency
bump), the release workflow builds it, commits it to a commit reachable only
from the release tag, and pushes just that tag — `main` stays source-only.
The same bundle also ships in the npm tarball via `package.json`'s `files`
allowlist, independent of `.gitignore`. PR CI still runs `yarn build` on
every PR (without committing the result) so a broken bundle is caught before
release.

The bundle is ESM (`dist/index.mjs`) because this package is
`"type": "module"`. The `.mjs` extension is load-bearing: it forces ESM
regardless of the nearest `package.json`'s `"type"` field, so the bundle
doesn't depend on ncc's auxiliary `dist/package.json` — which the build
script deletes after renaming the bundle.
